# Type-anchor fixture tooling

Type anchors are a focused fixture and debugging tool for comparing arbitrary
TypeScript descriptor shapes with compiler-produced Lean interface
descriptors. They are not part of shipped binding generation, coverage, or the
binding explorer.

Shipped bindings use a stronger and simpler path: a reviewed mapping selects a
TypeScript operation, the ABI policy produces a generated binding operation,
and the Lean declaration is rendered from that same record. The explorer joins
the generated operation with compiled reachability and provider-key evidence;
it does not compare the generated declaration back to its own input through an
independent anchor.

The standalone fixture remains useful when developing a new structural
comparison rule or inspecting a Lean interface that was not generated by the
binding tool. Its inputs live under `fixtures/type-anchors/` and all outputs
live under ignored `build/type-descriptors/` paths.

Anchors select the two descriptors to compare; they do not transform either
shape through authored receiver, effect, representation, or lifetime policy.
Those binding decisions belong exclusively to the generated binding operation.

Run the complete fixture check with:

```bash
npm run check:type-anchors
```

The individual debugging steps are:

```bash
npm run generate:type-descriptors
npm run generate:lean-type-anchor-manifest
npm run compare:type-anchors
npm run render:type-anchors
npm run render:type-anchors:html
```

The comparison report classifies explicit fixture relations as `exact`,
`compatible`, `weak`, or `missing`. These statuses describe only the compared
interface shapes. They do not verify JavaScript provider behavior, callback
lifetime, ownership, or semantic fidelity.

For shipped binding architecture, guarantees, and the primary interactive
report, see [SHIPPED_BINDINGS.md](SHIPPED_BINDINGS.md). For the translation
rules that create generated binding operations and Lean declarations, see
[BINDING_MODALITIES.md](BINDING_MODALITIES.md).
