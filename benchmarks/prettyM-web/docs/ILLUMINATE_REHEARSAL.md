# Illuminate example rehearsal

Illuminate is the first real second client of the standalone benchmark
application. It is selected with `?example=illuminate` and uses the same shell
and section format as `prettyM`, while retaining its player-specific controls
and execution contract. It compares the production JavaScript state machine
with typed VIR and FIR-native implementations of the same player trace. All
three inputs now come from clean immutable revisions. The staging remains a
local, non-publishable rehearsal until the package is built through the
canonical artifact catalog.

tick events use the bit-exact `dispatchTick` boundary. Both packages retain the
same persistent-checkpoint ownership protocol. The plotting adapter aggregates
their creation and dispatch intervals into the shared prepare, execute, decode,
and total phases while preserving the original intervals in the raw report.

Both packages were rebuilt twice from current FIR `main`. Their embedded
`BUILD.json` files record that exact FIR revision and clean Illuminate commit
`6f16cdc3`, where the frame-zero fix landed. FIR pins that revision in
`illuminate-source.json`; its gate and package publishers reject dirty or
mismatched checkouts. The staged Illuminate checkout may be a public descendant
as long as the receipt records it; the FIR package source remains the pinned
clean revision.

## Local staging

From this application directory:

```bash
npm run stage:illuminate -- \
  --source /path/to/illuminate \
  --native-package /path/to/illuminate-player-package \
  --selection-package /path/to/illuminate-selection-player-package \
  --vir-sdk /path/to/extracted/lean-vir-sdk
npm run test:illuminate
```

The VIR SDK may come directly from the `lean-vir-sdk` CI upload instead of the
Illuminate checkout. The stager verifies every SDK file against
`lean-vir-artifact.json` and every native package checksum, copies the inputs
under the ignored `artifacts/illuminate/` directory, and writes
`REHEARSAL.json` with the exact dirty/source/build identities. A v3-only local
rehearsal remains accepted when `--selection-package` is omitted. It does not
update the canonical artifact lock or publish anything.

The catalog and artifact-set formats can now describe this workload without
`prettyM`-specific paths or component names. FIR's full-action v3 producer now
has the required caller-owned output contract. The remaining producer work is
an equivalent selection-v4 export and an Illuminate/VIR module-set entry point
that accepts controlled checkout roots plus a fresh output path. The latter is
tracked in [`illuminate#44`](https://github.com/leanprover/illuminate/issues/44).

FIR's newer prepared HitScene handoff is not part of this artifact set. It is
compiler-admission evidence only: it deliberately provides no Wasm binary,
JavaScript adapter, input layout, or ownership contract.

The application-side `illuminate` staging adapter is complete. It verifies the
generic set, requires both FIR v3 and v4 plus all browser inputs below the
`illuminate/` namespace, copies only manifest-declared files, preserves
`ARTIFACT_SET.json` for report provenance, and replaces the staged directory
atomically. The existing local rehearsal remains supported until the remaining
producer request lands.

After those entry points land, add the `illuminate` record to
`artifact-builds.json`, build it through `_sources/`, and replace this local
receipt with an immutable artifact-set manifest.
